React state management cheatsheet

useState · useRef/useMemo/useCallback · Context API · Redux Toolkit + Thunk · useReducer

pick your tool
useState

Use when: local UI state in one component — toggles, form fields, counters, show/hide.

Skip when: multiple components need the same value.

const [count, setCount] = useState(0); setCount(c => c + 1);
Context API

Use when: sharing state across a subtree without prop drilling — theme, auth, locale.

Skip when: state changes frequently (causes full subtree re-render).

const Ctx = createContext(null); const val = useContext(Ctx);
RTK + Thunk

Use when: global app state, async data fetching, multiple slices, complex updates.

Skip when: the app is tiny — RTK is worth it at scale, overkill for a todo.

createSlice · configureStore createAsyncThunk · extraReducers
useReducer

Use when: complex local state with multiple sub-values or transitions (e.g. form with many fields, state machine).

Skip when: useState is enough — don't reach for this unless transitions are complex.

const [state, dispatch] = useReducer(reducer, init);
performance hooks — not state, just optimization
useRef

Use when: you need a mutable value that doesn't trigger re-renders — DOM refs, timers, previous value tracking.

const ref = useRef(null); ref.current.focus();
useMemo

Use when: a computed value is expensive and its deps rarely change. Memoizes the result.

const sorted = useMemo( () => items.sort(), [items] );
useCallback

Use when: a function is passed as a prop to a memoized child and you want to avoid re-creating it. Memoizes the function.

const fn = useCallback( () => doThing(id), [id] );
RTK anatomy
createSliceDefines name, initialState, and reducers. Auto-generates action creators and action types.
configureStoreCombines slices via reducer key. Includes redux-thunk middleware by default.
createAsyncThunkWraps async logic. Auto-dispatches pending / fulfilled / rejected lifecycle actions.
extraReducers + builderbuilder.addCase(thunk.fulfilled, (state, action) => {...}) — handles async results in a slice.
Immer (built-in)Inside createSlice reducers, mutate state directly — Immer converts it to an immutable update.
useSelectorReads from the store. Re-renders only when the selected value changes.
useDispatchReturns the dispatch function. Call it with an action creator or a thunk.
quick decision flowchart

Is the state needed by only one component? → useState (or useReducer if transitions are complex)

Is it rarely updated, shared across a subtree (theme, auth)? → Context API

Is it global app state or does it involve async fetching? → RTK + createAsyncThunk

Do you need a DOM node or a non-reactive mutable ref? → useRef

Is a computed value slow to derive? → useMemo

Passing a callback to a memoized child? → useCallback
